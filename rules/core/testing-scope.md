# 测试范围

为适配敏捷开发, 执行测试时默认只运行完成当前变更所必需的最小测试范围.

- 先根据修改的文件, 符号, 行为和依赖关系, 找出直接涉及或受影响的测试.
- 优先运行相关的 unit test, 目标 integration test, 目标 feature, 单个测试过滤器或最小验证命令.
- 不得为了“更放心”主动运行无关的全量测试, 全 workspace 测试或压力测试.
- 如果影响范围明确且局部, 不扩大测试范围; 如果影响范围跨模块或无法确定, 先向用户说明原因和成本, 再询问是否扩大验证.
- 用户明确指定测试范围时, 按用户指定执行.
- 项目 `AGENTS.md` 或其他已生效 RULES 明确要求的测试属于硬性门禁; 与本规则冲突时, 先按 `rule-conflict-resolution` 暂停并请用户决策.
- 每次测试后汇报实际执行的命令, 覆盖范围和结果; 不把未执行的测试描述为已验证.
