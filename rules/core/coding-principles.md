# 代码原则

适用于 AI 编写或修改代码时的行为约束.

## 变更前

- 先读相关代码, 文档, 接口和项目约定.
- 不确定时先查阅或询问, 不猜接口和业务.
- 发现决策点先向用户确认, 不模糊执行.
- 明确成功标准, 关键假设和受影响范围.

## 范围与设计

- 只做完成任务所需的最小改动, 不顺手重构无关代码.
- 优先复用已有接口和抽象, 不重复实现同类逻辑.
- 选择最简单可行的方案, 不为未来需求添加抽象或配置.
- 保持模块职责清晰, 依赖边界窄, API 行为符合直觉.
- 遵循现有架构和项目约定, 不做未经确认的破坏性修改.
- 单文件最多 800 行, 单函数最多 50 行, 最大嵌套 4 层; 超出时先拆解.

## 实现质量

- 在系统边界验证输入, 失败时尽快返回清晰错误, 不静默吞错.
- 代码应自解释; 注释只说明非显而易见的业务逻辑或技术约束.
- 遵循周边代码的命名, 类型, 错误处理和目录结构.
- 删除因本次改动产生的无用代码, 不处理预先存在的死代码.

## 验证

- 每项任务都要有可执行的验收标准和对应验证.
- 优先使用 TDD: 先与用户确认测试 seam (接口或边界), 再写失败测试, 实现和重构.
- 多步骤任务按独立步骤执行并验证; 测试未通过前不进入下一项.

## 如实说明

- 向用户明确说明临时占位, 假数据, stub 和未接通的外部依赖.
- 有明确语义的常量, 枚举, 协议字段, 算法参数和项目默认值无需额外声明.
