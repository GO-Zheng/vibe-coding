# Quick Test

针对当前仓库的 Git diff 做快速, 定向的测试和验证. `quick-test` 可以独立调用, 也可以作为 `quick` 流程中的测试阶段.

## 流程

1. 执行 `git diff HEAD` 获取当前分支相对 `HEAD` 的 staged 和 unstaged 变更.
2. 如果 diff 为空, 汇报没有可验证的变更并停止.
3. 根据 diff 中修改的文件, 符号, 行为和依赖关系, 识别直接涉及或受影响的测试.
4. 选择最小必要范围, 优先运行相关 unit test, 目标 integration test, 目标 feature, 单个测试过滤器或最小验证命令.
5. 如果影响范围不明确, 先向用户说明扩大验证的原因, 范围和成本, 询问是否扩大.
6. 按确认的范围执行测试. 任一测试失败后立即停止, 汇报失败原因, 不自动修复或重试.
7. 汇报实际执行的命令, 覆盖范围, 结果和未验证部分.

## 约束

- 不得为了“更放心”运行无关的全量测试, 全 workspace 测试或压力测试.
- 用户明确指定测试范围时, 按用户指定执行.
- 项目 `AGENTS.md` 或其他已生效 RULES 的硬性测试门禁与当前范围冲突时, 按 `rule-conflict-resolution` 暂停并请用户决策.
- 不得把未执行的测试描述为已验证.
